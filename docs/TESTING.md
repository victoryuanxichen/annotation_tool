## Synthetic test videos

`npm run gen:videos` renders frames in Node and encodes them with ffmpeg/libx264. Every frame shows its own
frame number as seven-segment digits and as a 24-cell binary barcode (guard bits + 20-bit number + mod-4
checksum). Tests decode the barcode from the app's canvas to check which frame is actually on screen.
`manifest.json` holds ffprobe's ground truth: frame count, per-frame pts, SHA-256.

| File | What it exercises |
| --- | --- |
| `cfr25_bframes.mp4` | 25 fps constant, 250 frames, 3 B-frames (CTS reordering + edit list) |
| `ntsc2997.mp4` | Fractional 30000/1001 fps, 300 frames |
| `vfr_mixed.mp4` | True variable frame rate (21 / 52.7 / 84.4 ms + periodic 50 ms gaps), timescale 90 kHz |
| `baseline24_nob.mp4` | Baseline profile, no B-frames, 24 fps |
| `open_gop30.mp4` | Open-GOP: leading B-frames reference the previous GOP, recovery-point I-frames |
| `tiny3.mp4` | Three frames (boundary edge cases) |
| `long720p_gop300.mp4` | 1280×720, 3600 frames, 300-frame GOPs (seek latency, scrubbing) |
| `same_name_a/b.mp4` | Different content, used under the same file name in two folders |
| padded copies (generated by tests) | Same video plus a trailing MP4 `free` box, up to ~2 GB, so hashing takes seconds |

## What was verified, by requirement

### Frame accuracy (REQUIREMENTS §4)

- **Index vs ffprobe** (`tests/unit/mp4.test.ts`): for all 9 fixtures, the frame count and every frame's
  µs timestamp equal ffprobe's presentation-order pts exactly. Also checked: the frame↔sample mapping is a
  bijection, decode starts at a real IDR/recovery point, and truncated or non-MP4 input is rejected.
- **Pixels vs counter** (`player.spec.ts`, 48 tests over 7 fixtures): first, middle and last frames; every
  7th frame (every frame for files of 300 frames or fewer); random seeks; +1 stepping through whole files
  and −1 stepping backwards across GOP boundaries; 3 × 60 random seeks in ~300 ms, sampled every animation
  frame; 1x and 2x playback, then pause. In every case the barcode on the canvas, `displayedFrame` and the
  requested frame agree. Error paths covered: WebCodecs missing, unsupported codec, read failure, corrupt
  data. Also: a second video fully replaces the first, and the frame stays exact after a canvas resize.
- **Through the real UI** (`accuracy.spec.ts`, cfr25 / ntsc2997 / vfr_mixed / open_gop30 / tiny3):
  - Z/X and the jump field: the counter, barcode and timecode equal the manifest.
  - Adjacent segments via E: the first segment's end equals the second's start, and the "last frame" column
    is end − 1. R gives end = N.
  - CSV and JSON exports, parsed by an independent parser in the test: `start_us`/`end_us` equal ffprobe pts,
    `duration_us` is used for N, and the SHA-256 and frame count match.
- **Round trip**: a fresh browser profile opening the same folder loads the sidecars automatically. For every
  segment, `start_frame` and `end_frame − 1` are seeked through the UI and the barcode shows exactly those
  frames. Manual import of the JSON, and separately of the CSV, gives the same result.
- **Marking during a seek**: W/E/Q pressed while a seek is in flight commit the frame that gets displayed.
  When further navigation replaces that target before it is shown, the mark is refused rather than committed
  at a later frame (this was a real bug, found and fixed during review).
- **Independent recovery** (manual, see the walkthrough below): an export from the app was checked with
  `scripts/recover-frames.mjs` (ffprobe), with `ffmpeg select=between(n,…)`, and with a PyAV script. All three
  recovered exactly the annotated frames.

### Interaction quality (REQUIREMENTS §2–3)

`interaction.spec.ts`, driven with real Playwright mouse and keyboard events:

- **Rapid timeline drag** on the 720p long-GOP video, sampled every animation frame: the counter text,
  `displayedFrame` and the barcode never disagree. After release, the final frame is the frame under the
  pointer. Holding D steps monotonically.
- **Control stability**: bounding boxes of Prev/Next, transport buttons, frame field, counter, timeline,
  chips 1–5, the four marking buttons, Export and the batch list are identical (±0.5 px) across these states:
  loading, ready, playing, seeking, pending start, segment selected, long path, toast visible, and each
  bottom tab.
- **Shortcut suppression**: typing `qwer adzx` and Space in the jump field, custom phase name, checkpoint
  name and a select does not mark, step or play. Space with a button focused toggles play without pressing
  the button. Esc, 1–5 / Shift+1–5, and undo/redo also work.
- **Background work** (`long720p_gop300` padded to ~2 GB):

  | Metric | Measured |
  | --- | --- |
  | Video ready after open | 95 ms (index reads only `moov`) |
  | Full SHA-256, in a worker | 5.2 s |
  | Playback while hashing | 29.8 fps presented, 0 frames backwards, 0 dropped |
  | Playback during background verification of another video | 29.8 fps |
  | Main-thread long tasks during hashing / verification | 0 / 0 |
  | Marking during hashing | Q/W boundaries exact (barcode-verified) |

- **Seek latency**, long-GOP 720p, 60 random seeks: p50 39 ms, p95 67 ms, max 72 ms.

### Batch, sidecars, exports (REQUIREMENTS §5)

`batch.spec.ts` (17 tests):

- Recursive listing with relative paths. Sorting by name, modified time and size, ascending and descending;
  Prev/Next follow the sort order. Switching works from both the list and Prev/Next.
- **Same-name mismatch**: caseA's export copied beside `caseB/same_name.mp4` is flagged *Mismatch* (SHA-256
  problem explained) and never loaded.
- **Sidecar discovery**: `stem.csv`, `stem.phases.json` and `stem_annotations.csv` are found. Status goes from
  *Not verified* to *Annotated* after background verification. A file whose name matches two videos goes to
  the longer stem.
- **Sidecar vs existing draft**: the import-choice dialog appears. *Use file* replaces the draft and creates an
  `auto-before-import` checkpoint; *Keep draft* keeps the draft. Corrupted sidecars (bad boundaries or frame
  count) are rejected with reasons.
- **Export on switch**: CSV beside the video by default. JSON, Both and Download (a real download event) are
  respected when chosen.
- **Denied write permission and write failures** (fault injection through the e2e test hook): the switch is
  blocked, the dialog explains recovery, *Download instead* works, and *Switch without exporting* keeps the
  draft in IndexedDB.
- **Empty draft**: deleting all segments of an annotated video and switching writes the one-row empty form,
  which re-imports as annotated with 0 segments.
- **Single MP4 without folder access** shows the "allow folder access" notice. A read-only folder falls back
  to downloads.

### Recovery (REQUIREMENTS §5)

`recovery.spec.ts` (14 tests):

- **Crash recovery**: segments marked, then the page is killed without `beforeunload` (and, separately, hard
  reloaded). Reopening the folder restores identical segments.
- **Crash during hashing**: an edit made while the full SHA-256 of a large padded file is still running
  survives a kill (saved under the provisional key, promoted later). This was a gap found in review and fixed.
- **Renamed copy**: the draft is found by content hash, including a mark made during hashing on the renamed file.
- **Checkpoints**: create → edit → restore. An automatic pre-restore checkpoint holds the edited state.
- **Stale tab**: two tabs on one video. Tab B never silently overwrites tab A's revision (checked in
  IndexedDB). *Load newer* / *Keep mine* checkpoint first. Autosave keeps working for the next video after
  leaving a conflicted one.
- **Unexported-changes warning on the last video**: the native `beforeunload` dialog fires, and does not fire
  once everything is exported. The in-app "close folder" confirm also works.
- **Offline**: with the network disabled after load, annotate, export and switch videos work, and no request
  leaves 127.0.0.1. Opening a video right after load while offline also works. The **production build**
  served by `server/serve.mjs` loads and works with zero external requests.

## Desktop walkthrough (real browser, mouse + keyboard)

Done in the Claude desktop app's built-in Chromium browser at 1440×900, against the dev server. A
five-video folder (`case_01_cfr25`, `case_02_ntsc`, `case_03_vfr`, `caseA/same_name`, `caseB/same_name`)
was placed in the browser's private file system and opened through the test hook, since the native folder
picker cannot be driven remotely. Everything after that used real mouse clicks and key presses:

1. Switched the UI language from 繁中 to English with the top-bar toggle.
2. Clicked the *Preparation* chip, pressed D×5, Q, D×40, E, then key 2 (*Calot triangle dissection*). Clicked
   the timeline at about frame 118, then pressed W. Result: `[5,45)` and `[45,118)`. The counter showed 118
   and the image showed 00118. The hover preview labelled its keyframe (≈ keyframe 100). The status bar showed
   *Saved* and *Unexported changes*.
3. Dragged quickly across the timeline. A capture taken mid-drag showed the counter at 130 matching the image,
   with the pending target `→ 221` shown faintly. After release, counter = barcode = displayed = 221.
4. Pressed R with no pending start. The mark was refused with "Set a start first (Q)."
5. Clicked **Next**. The CSV was written beside the video (BOM bytes `EF BB BF`, CRLF, two rows), case_01
   became *Annotated*, and the app moved to case_02. The exported file passed `scripts/recover-frames.mjs`
   (sha, frame count, duration, all boundary times). ffmpeg extracted boundary frames 5, 44, 45 and 117 and
   they show those numbers.
6. Clicked `caseB/same_name.mp4` (the last of 5) in the list, then pressed Z, 4, Q, X, R. Result: `[0,150)`
   with N = 150, and the last frame (149) was confirmed by the barcode. Next is disabled on the last video. A
   cancelable `beforeunload` was prevented (native leave warning armed, 1 unexported video).
7. Reloaded the page. The folder reconnected automatically, case_01's segments were restored, and caseB was
   still listed as *Draft*.
8. Pressed Shift+/. The help dialog opened with the full shortcut map and the half-open explanation.

Finding from the walkthrough, fixed: the browser automation sends Shift+/ as `key='/'` with an empty `code`,
which the help shortcut ignored. `src/ui/shortcuts.ts` now also accepts `key === '?'` and Shift + `key === '/'`.

## Not covered / limitations of this test record

- Only Chrome on macOS was tested. Windows, Linux, Edge, Firefox and Safari were not.
- The native file and folder pickers and Chrome's permission prompts cannot be automated. Tests use the
  browser's private file system and a fault-injection hook (`window.__pa`, only present in dev or with
  `?e2e=1`) that exercises the same code paths after the picker.
- Real surgical recordings (hour-long, 1080p/4K, recorder-specific MP4 quirks) were not used. Only synthetic
  video was allowed. The largest file tested was ~2 GB (padded), the longest 3600 frames.
- Screen-reader behaviour was not tested beyond ARIA labels and live regions being present.
